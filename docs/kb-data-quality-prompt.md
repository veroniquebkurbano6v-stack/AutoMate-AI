# 知识库 SOP 数据生产规范 Prompt

> 适用范围：AutoMate-AI 端侧知识库（`app/src/main/assets/kb/sop_raw/*.json`）的新增、改写、审核。
> 配套审查脚本：`eval/audit_sop_quality.py`（扫描 587 条 SOP，检出含糊描述 / 未搜索优先 / 占位词问题）。
> 配套检索评测：`eval/eval_retrieval.py`（bge-small-zh 向量 + 关键词 RRF 融合，top-3 命中判定）。

---

## 一、数据目标（先明确"为什么"）

知识库中的每条 SOP 是一份"人在真实 App 里完成一个任务的逐步操作手册"。端侧 agent 通过
`kb_read` 检索到它后，会**逐条照着 goal 描述去点击/输入屏幕上的真实控件**。

因此 SOP 的质量 = agent 能否不借助截图、不靠猜、稳定复现操作。任何"模糊表述"都会让
agent 无从下手或点错位置。

---

## 二、硬性要求（写数据时必须满足，缺一不可）

### 要求 1：能搜索，一定搜索（最高优先级）

凡是**可以通过输入关键词锁定目标**的信息，步骤中**必须**包含"点击搜索框 → 输入关键词 →
点击搜索结果条目"的完整链路，禁止"从列表里挑 / 直接点某个对话 / 翻找"这类碰运气写法。

需要搜索锁定的典型对象：

| 对象类型 | 例子 | 必须写的链路 |
|---|---|---|
| 微信/QQ 联系人、群组 | 分享给"孙杰"、发给"工作群" | 右上角搜索图标 → 输入名字 → 点搜索结果条目 → 进入会话 |
| 店铺/商户 | 找"锦里火锅MOMOPARK店" | 搜索框输入店名 → 点搜索结果条目 |
| 菜品/商品 | 点"香辣土豆片夹馍" | 搜索框输入菜名 → 点结果条目 |
| 地点/POI | 导航去"西安东站" | 搜索框输入地点 → 点结果条目 |
| 歌曲/影视 | 播"三体"第 5 集 | 搜索框输入名称 → 点结果条目 |

> 为什么必须搜：结果列表顺序、位置、是否在首屏都不确定，唯独"搜索结果条目"是
> 可控、可验证的锚点。**用搜索锁定，就是给 agent 一个确定性的目标。**

### 要求 2：UI 描述必须具体到"哪个控件"

每步 goal 要能直接映射到一个真实控件，格式：
`点击 + 位置 + 控件名（+ 目的）`。

| ✅ 合格 | ❌ 不合格 |
|---|---|
| 点击微信**右上角的搜索图标** | 点击搜索（哪里的搜索？） |
| 点击**屏幕中间的**搜索框（高德地图） | 点击输入框（哪个页面的？） |
| 点击**底部导航栏**中的'我的'按钮 | 点击我的 |
| 点击**分享面板中的**'微信'图标 | 点击分享 |
| 点击**详情页底部的**'分享'按钮 | 点击分享按钮 |

位置词（右上角/中间/顶部/底部/左侧/搜索面板中/聊天列表上方…）+ 带引号的按钮文字，二者至少要有其一。
**位置以 App 实际 UI 为准**：高德地图主页的搜索框位于**屏幕中间**（不是顶部），微信聊天列表页的搜索入口是**右上角搜索图标**。

### 要求 3：禁止泛化占位词

步骤 goal / expected **不得**出现以下把具体对象抽象成占位词的写法（检索靠 task_name /
keywords 泛化即可，步骤必须具体）：

```
指定地点 / 指定场所 / 指定餐厅 / 指定店铺 / 指定菜品 / 指定联系人 / 指定位置
特定餐厅 / 特定店铺 / 特定菜品 / 特定场所 / 特定地点 / 特定内容
对应店铺 / 对应联系人 / 对应地点 / 相关的条目 / 合适的 / 相应的 / 目标联系人
```

反例（知识库现存问题）：
- "点击搜索栏中的'目的地'文字区域" → 应为"点击**屏幕中间搜索框**中的占位文字"
- "在文本输入框中输入'联系人'" → 应为"在搜索框中输入**联系人姓名**"
- "选择排序方式为距离优先"（可接受）但"点击'指定场所'条目" → 应为"点击**评分最高**的店铺条目"

### 要求 4：步骤粒度一致

- 两步能合并的连续动作合并：**"点击搜索框" + "输入关键词" 合并为一步**
  （goal 写成"点击屏幕中间的搜索框输入'火锅'以搜索附近的火锅店"，action_type 为 `type`）。
- 合并后每步仍只包含**一个明确的交互动作**（点击某控件 / 输入某文本），不要一步里做三件事。
- goal 平均长度不宜低于 10 字（现库 89 条低于此线，多为含糊短句）。

### 要求 5：进入 App 后必须先导航到目标界面

打开 App 后的默认界面**不一定就是操作目标界面**，步骤必须覆盖从"桌面图标"到
"操作目标界面"的完整导航，并点名导航控件的**位置**，不得假设打开即到达。

| ✅ 合格 | ❌ 不合格 |
|---|---|
| 点击界面**底部、下方导航栏上方一点**的'正在播放'音乐图标，进入当前播放歌曲的播放界面 | 点击分享按钮（假设已在播放界面） |
| 点击**底部导航栏**中的'我的'按钮进入个人中心 | 进入收藏夹页面（缺导航） |
| 点击**主界面顶部**的搜索框 | 输入关键词（假设已在搜索页） |

> 例：网易云音乐进入后默认在"发现"页，要分享"当前播放的歌曲"必须先点界面底部
> '正在播放'图标（位于下方导航栏上方一点）进入播放界面，再点右上角分享按钮。

### 要求 6：字段完整

```json
{
  "sop_id": "16位十六进制",
  "original_task_name": "用户原话（含真实对象名，如'把当前位置发送给微信好友韩磊'）",
  "task_name": "泛化任务名（'把当前位置发送给微信联系人'，供检索）",
  "app_name": "主操作App，如 微信 / 高德地图",
  "source": "cagui_auto",
  "difficulty": "L2/L3/L4",
  "domain": "社交 / 导航 / 购物 / 媒体 / 生活服务 / 效率 / 查询",
  "keywords": ["App名", "对象类型", "动作", "关键控件"],
  "steps": [
    {"step_order": 1, "goal": "点击手机桌面上的微信应用图标", "expected": "进入微信主界面", "action_type": "click"},
    {"step_order": 2, "goal": "点击页面顶部的搜索框输入'韩磊'", "expected": "显示匹配联系人的搜索结果", "action_type": "type"},
    {"step_order": 3, "goal": "点击搜索结果中的'韩磊'条目", "expected": "进入与韩磊的聊天界面", "action_type": "click"}
  ]
}
```

- `action_type` 只使用 `click` / `type` / `long_press` / `swipe`。
- `keywords` 必须覆盖：App 名 + 对象类型 + 动作 + 跨 App 目标（如"分享""微信"），
  这是关键词检索的一半权重，直接影响召回。

## 三、微信 / 聊天类场景的固定做法（重点）

凡涉及"给某个联系人/群组发送/分享/转发"的 SOP，分享面板之后的步骤**必须**是：

1. 点击分享面板中的'微信'图标 → 进入微信分享界面
2. 点击微信分享界面**上方的搜索框**，输入联系人姓名 → 显示匹配条目
3. 点击搜索结果中的对应联系人条目 → **弹出"确认/取消"对话框**
4. 点击对话框中的'确认'按钮 → 任务完成

**禁止**：直接"点击聊天列表中的联系人对话条目"（列表顺序不可控）、
"选择聊天对象"（没说怎么选）、"点击目标联系人"（没有定位路径）。
**禁止**：选中联系人后漏掉"确认"对话框直接结束（分享/转发均有确认环节）。

> 参考正例：`a1b2c3d4e5f60718`（高德找评分最高火锅店分享给微信联系人）第 8-10 步。
> 现存反例（应修正或删除）：`b02eecc5671fff72`（把当前位置发送给微信联系人）、
> `4271d22d1f4c258d`（转发消息到群组）——均无搜索定位联系人步骤。

## 五、自检清单（提交 SOP 前逐条勾选）

- [ ] 能搜索的对象（联系人/店铺/菜品/地点/歌曲）**全部**走了"搜索框 → 输入 → 点结果"链路？
- [ ] 每步 goal 都能说出"点哪个控件"（位置 + 控件名 + 引号文字）？
- [ ] 全文无占位词（指定××× / 特定××× / 对应××× / 相关的内容）？
- [ ] "点击搜索框 + 输入"已合并为一步（action_type=`type`）？
- [ ] 微信分享/发送场景 = 搜索框输入联系人 → 点结果 → 点'确认'对话框？
- [ ] 进入 App 后是否先导航到目标界面（如点底部'正在播放'图标进播放页）？
- [ ] 选中联系人后是否遗漏"确认/取消"对话框？
- [ ] 字段完整（sop_id/original_task_name/task_name/app_name/source/difficulty/domain/keywords/steps）？
- [ ] keywords 覆盖 App 名 + 对象类型 + 动作 + 跨 App 目标？

## 六、新增数据后的验证流程

1. 新增 JSON → `app/src/main/assets/kb/sop_raw/`
2. `python eval/audit_sop_quality.py`：确认新条目不在"推荐删除候选"列表
3. `eval/eval_retrieval.py` 的 `QUERIES` 追加对应 query，确认 top-1 命中且分数 ≥ 0.3
4. 设备端：重新 build APK → 设置页"重新入库"重建 kb.db（30-60s）→ 实测任务
5. 录制 demo 视频，按 `demo/` 目录命名规范（`0X_*.mp4` + 封面图）归档

## 七、供直接复用的 Prompt（喂给生成/改写数据的模型）

> 把下面整段作为 system prompt，配合上述规范使用。

```
你是移动端 UI 自动化知识库的 SOP 数据工程师。你的任务是编写/改写 JSON 格式的
操作手册（SOP），供端侧 agent 按步骤在真实 App 里执行。

硬性规则（违反任意一条即不合格）：
1. 能搜索一定搜索：目标对象（联系人、店铺、菜品、地点、歌曲）必须通过
   "点击搜索框 → 输入关键词 → 点击搜索结果条目"锁定，禁止从列表盲选。
2. 每步 goal 必须指明具体 UI 控件：位置（右上角/顶部/底部/面板中）+ 控件名
   （搜索框/搜索图标/按钮文字，按钮文字用单引号包裹），例如
   "点击微信右上角的搜索图标"。
3. 禁止占位词：不得出现 指定地点/特定餐厅/对应联系人/相关的内容 等抽象表述；
   步骤里一律用具体对象，泛化只放在 task_name 和 keywords 字段。
4. 步骤粒度："点击搜索框"与"输入关键词"合并为一步（action_type 为 type）；
   其余每步只包含一个交互动作。
5. 微信发送/分享场景固定链路：分享面板点'微信'图标 → 点微信分享界面上方的
   搜索框输入联系人姓名 → 点搜索结果条目 → 在弹出的"确认/取消"对话框里点'确认'按钮。
6. 进入 App 后必须先导航到目标界面：若打开后的默认界面不是操作目标界面，必须
   先写一步导航（点名控件位置，如"点击界面底部、下方导航栏上方一点的'正在播放'
   音乐图标进入播放界面"），不得假设打开 App 即处于目标界面。
7. 字段必须完整：sop_id(16位hex)、original_task_name(用户原话)、
   task_name(泛化名)、app_name、source(cagui_auto)、difficulty(L2-L4)、
   domain、keywords(含App名+对象+动作+跨App目标)、steps(step_order/goal/expected/action_type)。

输出格式：仅输出一个合法的 JSON 对象，不要输出任何解释文字。
```

## 八、当前库审查结论（2026-08-16，587 条）

- **达标基准**：354 条（有搜索步骤 + 无占位词 + goal 均长 ≥12 字 + 步数 ≥3）
- **推荐删除/重写候选**：139 条，主要问题集中在：
  - 微信"转发/分享/发位置/发语音"类：**未用搜索框定位联系人**（约 108 条涉聊天场景未搜索，占比最高）
  - 整条无搜索/输入步骤：69 条
  - 含占位词：89 条（高频：对应地点 22 / 特定餐厅 11 / 指定联系人 10 / 相关的内容 9 / 特定店铺 8）
- 完整候选清单见 `eval/audit_sop_quality.py` 运行输出（`--kb-dir` 指向 sop_raw 目录）。
