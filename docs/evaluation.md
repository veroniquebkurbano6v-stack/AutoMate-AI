## 知识库检索评测

### 配置
- 嵌入模型：bge-small-zh-v1.5 INT8 ONNX（端侧同款）
- 检索：向量(task 0.7 + keyword 0.3) + 关键词子串 → RRF 融合(RRF_K=60)
- 知识库：586 条 SOP JSON
- 评测集：10 条 query，覆盖购物/导航/社交/视频/生活/跨App；query 表述与知识库
  实际条目一致（注：饿了么平台已下线，知识库为「淘宝闪购外卖」，故 query 1 用淘宝闪购）

### 已知局限
- **检索 query 需与知识库平台口径一致**：早期评测集 query 1 使用了已下线平台名
  "饿了么"，与知识库「淘宝闪购外卖」条目（sop 006b3e83f8）不匹配导致未命中；
  已按实际知识库数据修正评测集（query 1 改用淘宝闪购表述，见上表）后全部命中。
  这一发现说明端侧检索依赖嵌入模型的平台词理解，后续可增加平台别名表
  （如"饿了么 → 淘宝闪购"）进一步增强鲁棒性。

## 视觉鲁棒性 / 提示词消融评测

针对"屏幕视觉是否把广告/干扰弹窗误当正常页面"这一执行引擎核心风险，
用真实 App 截图做了三组消融实验（实验数据与脚本见 [temp/](../temp/)）：

**评测集**：38 个真实截图样本（`temp/ad_test_samples/`），覆盖
QQ音乐 / 酷狗 / 优酷 / 网易云 / 淘宝 / 高德 / B站 / 大众点评 / 小红书，
标注三类：`NORMAL` 正常页面 / `POS广告` 广告弹窗 / `SPEC规格` 规格选择页。

### 1. 提示词消融（15 配置 × 11 样本 = 165 次调用）

| 提示词变体 | 图片压缩策略 | 样本数 | 准确率 |
|-----------|-------------|--------|--------|
| P1 简短指令 | C1 原图 / C2 长边768 / C3 长边768q70 | 11 | **100% / 100% / 100%** |
| P2 详细定义 | 同上 | 11 | **100% / 100% / 100%** |
| P3 角色规则 | 同上 | 11 | **100% / 100% / 100%** |
| P4 JSON 输出 | 同上 | 11 | **100% / 100% / 100%** |
| P5 示例引导 | 同上 | 11 | **100% / 100% / 100%** |

结论：广告识别对提示词风格（简短/详细/角色/JSON/示例）和图片压缩
（原图/768/768+q70）均不敏感，**5 种提示词 × 3 档压缩全部 100% 正确**，
说明识别能力主要来自视觉模型本身，而非提示词工程技巧。

### 2. 温度消融（19 样本）

| 配置 | 准确率 |
|------|--------|
| A_简短 @ temp=0.1 | 19/19 = **100%** |
| A_简短 @ temp=0.5 | 19/19 = **100%** |

### 3. GUI-Plus 视觉执行（生产视觉模型）

| 实验 | 样本 | 结果 |
|------|------|------|
| 广告识别（label POS/NORMAL vs pred ad/normal） | 15 | 14/15 = **93%** |
| 关闭广告动作（酷狗/优酷/QQ音乐） | 3 | 3/3 与人工标注一致 |
| QQ音乐广告关闭坐标输出（close + [864,78] 等） | 4 | 4/4 输出可执行坐标 |

### 已知局限
- GUI-Plus 广告识别 15 样本中有 1 例正常页被误判为广告（93% 而非 100%），
  属于视觉模型固有误报；执行引擎另有 `supervised` 用户确认兜底，不会直接点错。
- 视觉决策实验中发现个别"幻觉 auto"现象（场景名标注 `qwen幻觉auto`），
  已通过关闭广告动作改为显式坐标 + 置信度输出缓解（见 scenario_c 结果）。
